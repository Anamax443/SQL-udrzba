Jak to řeší návrh:
  • Diagnóza (kap. 2.3a): Log backup je ve FULL recovery jediný způsob, jak se log recykluje — není to volitelná ochrana.
  • Příčina (kap. 5.1): Okno log záloh 05:30–15:46, mimo něj log roste na strop 100 GB.
  • Řešení (kap. 7.1, Fáze 1): Rozšířit okno na 00:00–23:59, všech 7 dní.
  • Monitoring (kap. 11.1): Alert na chybu 9002 do ITDashboardu.

3.2 Event ID 208 — Emergency_Cache_Warming Job Failed ⚠️

warn;208;SQLSERVERAGENT;Application
"SQL Server Scheduled Job 'Emergency_Cache_Warming' - Status: Failed -
 Invoked on: Schedule 3094 (Every_5_Min_PLE_Check).
 The last step to run was step 1 (Check_PLE_And_Warm2)."
MetrikaHodnota
Počet výskytů8×
Časy (SELČ)05:55, 06:10, 06:35, 06:50, 07:15, 07:30, 07:55, 08:10
Interval~15 min (schedule deklaruje 5 min)
Selhávající krokCheck_PLE_And_Warm2

Job se snaží řešit nízký PLE (Page Life Expectancy) — metriku ukazující, jak dlouho se stránky drží v buffer poolu. Nízký PLE znamená časté čtení z disku místo z paměti.

⚠️ Mezera v návrhu: Návrh tento job přímo nezmiňuje. Pokud je příčinou selhání plný log (9002), řeší to Fáze 1 nepřímo. Chybí ale monitoring PLE jako takový. Doporučuji doplnit do kapitoly 11: 
SELECT counter_name, cntr_value AS ple_seconds
FROM sys.dm_os_performance_counters
WHERE object_name = 'SQLServer:Buffer Manager'
  AND counter_name = 'Page life expectancy';
-- práh: < 300 s = varování

3.3 Event ID 4098 — Group Policy Drive Maps ℹ️

warn;4098;Group Policy Drive Maps;Application
"The user 'Y:' preference item in the 'MAP_Network_Drive' GPO did not apply
 because it failed with error code '0x80070035 The network path was not found.'"

GPO MAP_Network_Drive se snaží mapovat síťové disky Y: a I:, ale cílový server není dostupný. Jde o infrastrukturní problém (síť / GPO), nikoli problém zálohování.

➖ Doporučení: Řešit odděleně v rámci správy GPO — ověřit dostupnost cílového serveru, případně vyjmout SQL server ze scope tohoto GPO. Návrh zálohování to správně neřeší.

3.4 Event ID 1803 — TPM Key Exchange Key Not Found ℹ️

err;1803;Microsoft-Windows-TPM-WMI;System
"A PK-signed Key Exchange Key (KEK) cannot be found for this device."

Chyba vTPM ve VMware VM (FirmwareManufacturer: VMware, Inc.). Souvisí s BitLockerem / Secure Boot, nikoli se zálohováním databáze.

➖ Doporučení: Předat týmu správy VMware / bezpečnosti. Ověřit konfiguraci vTPM. Mimo scope návrhu zálohování.

Ověřovací skript po nasazení Fáze 1

-- Mělo by vrátit 'NOTHING' nebo 'CHECKPOINT', ne 'LOG_BACKUP'
SELECT name, recovery_model_desc, log_reuse_wait_desc
FROM sys.databases
WHERE name = 'NAV-LIVE';

-- Stáří poslední log zálohy (mělo by být < 90 min)
SELECT DATEDIFF(MINUTE, MAX(backup_finish_date), GETDATE()) AS log_stari_min
FROM msdb.dbo.backupset
WHERE database_name = 'NAV-LIVE' AND type = 'L';
